# hanime1 建档自动化验证报告

验证日期：2026-07-20

验证对象：

- 作品名：姉SUMMER！
- 用户给定搜索入口：https://hanime1.me/search?query=&type=&genre=%E8%A3%8F%E7%95%AA&sort=&date=&duration=
- 实测搜索 URL：https://hanime1.me/search?query=%E5%A7%89SUMMER%EF%BC%81&type=&genre=%E8%A3%8F%E7%95%AA&sort=&date=&duration=
- 本地目录：`D:\HAnime\姉SUMMER！`

## 结论

hanime1 适合做“候选信息来源”，不适合做无确认的全自动建档来源。

原因有三点：

1. 站点没有稳定公开 API，后台 HTTP 请求和 headless Edge 实测都被 Cloudflare 403 拦截。
2. hanime1 的信息更偏逐集页面，能补标题、副标题、发布年月、制作商、tag、每集封面，但角色顺序、简介、主封面、官方链接仍需要人工判断或从其他来源补。
3. tag 本身需要清洗和分类映射，不能把网页 tag 原样写进数据库，否则会继续出现“公众场合/精神崩溃/校园”等分类错位问题。

因此推荐实现成：建档助手里增加“hanime1 辅助填充”功能，让软件在内置浏览器会话中搜索和解析，生成候选草稿，最后由你确认后再写入 meta.json。

补充验证：用户提供 `Ctrl+U` 保存的搜索页和详情页 HTML 后，已确认页面源码里包含足够字段，可以离线解析。也就是说，真正难点不是“页面有没有信息”，而是“怎么稳定拿到登录/Cloudflare 后的页面内容”。如果由用户在浏览器里打开后保存源码，或者软件内置 WebView 让用户打开页面再解析 DOM，这条路是可行的。

## hanime1 可用字段判断

按用户描述和站点页面形态，hanime1 对建档最有价值的字段是：

| 字段 | 自动化价值 | 可靠性 | 处理方式 |
| --- | --- | --- | --- |
| 搜索结果封面 | 高 | 中 | 作为候选图预览，不直接当最终主封面 |
| 搜索结果标题 | 高 | 中 | 用于候选匹配，不覆盖用户填写标题 |
| 详情页主标题 | 高 | 中 | 填入草稿标题，需确认 |
| 详情页副标题 | 高 | 中 | 填入对应集 `subtitle` |
| 发布年月 | 高 | 中 | 规范化成 `YYYY-MM` |
| 制作商 | 高 | 中 | 填入 `studio` |
| tag | 高 | 低到中 | 需要清洗、分类、去噪、人工确认 |
| 本集封面 | 高 | 中 | 可下载为 `cover_epN`，保存前需预览 |
| 角色名 | 低 | 低 | 不建议自动填，仍由用户手填 |
| 简介 | 低 | 低 | 不建议依赖 hanime1，保留手填/粘贴 |
| getchu 链接 | 无 | 无 | hanime1 不能提供，仍手填或另做 getchu 辅助 |

## 已确认的 DOM 解析点

基于 `Ctrl+U` 样本，建议解析器优先使用以下稳定点：

| 页面 | 字段 | 解析位置 |
| --- | --- | --- |
| 搜索页 | 候选链接 | `a[href^="https://hanime1.me/watch?v="]` |
| 搜索页 | 候选封面 | 候选卡片内第一个 `img[src]` |
| 搜索页 | 候选标题 | `.home-rows-videos-title` |
| 详情页 | 当前详情链接 | `link[rel="canonical"]` |
| 详情页 | 完整标题 | `#shareBtn-title` 或 `meta[property="og:title"]` |
| 详情页 | 当前集封面 | `meta[property="og:image"]`，兜底用 `video[poster]` |
| 详情页 | 制作商 | `#video-artist-name` |
| 详情页 | 发布日期 | 描述区里的 `YYYY-MM-DD` 文本 |
| 详情页 | tag | `.single-video-tag a`，去掉括号数量 |
| 详情页 | 系列标题 | `#playlist-top-block` 附近的 playlist 链接文本 |
| 详情页 | 同系列集数 | `#playlist-scroll .playlist-hover-wrap[data-href]` |

副标题拆分建议：

1. 先从完整标题去掉 `[中文字幕]` 这类方括号尾巴。
2. 用系列标题 `姉SUMMER！` 从开头剥离。
3. 去掉集数卷标，例如 `上巻`、`下巻`、`第1話`、`#1`，但保留原文用于候选展示。
4. 剩余部分作为 `subtitle`，本例得到 `バ、バカァァッン`。

注意：搜索页标题里的 `姐SUMMER！ 1/2` 是中文化简写，不应直接写入 `meta.json` 的 `subtitle`。

## 推荐实现方案

### 入口位置

放在建档助手的“作品目录/官方日文名”区域下面，按钮名建议：

```text
hanime1 查找候选
```

原因：这个动作发生在读取目录之后、编辑 meta 之前，属于“给当前未建档目录找候选资料”，不应该放主库，也不应该放设置。

### 交互流程

1. 用户进入未建档页面，点某个目录的“建档”。
2. 建档助手读取本地视频，按文件名 `#1/#2/#3` 生成逐集草稿。
3. 用户点“hanime1 查找候选”。
4. 软件用当前标题或官方日文名打开 hanime1 搜索。
5. 显示搜索候选：封面、标题、发布日期、链接。
6. 用户勾选对应的第几集，例如候选 A 对应本地第 1 集，候选 B 对应本地第 2 集。
7. 软件解析详情页，把副标题、发布年月、制作商、tag、本集封面填入草稿。
8. tag 进入“待确认”状态，显示原始 tag、清洗后 tag、分类结果。
9. 用户确认后保存 meta，再导入主库。

### 技术路径

最稳定的方式不是后台 HTTP 抓取，而是使用 Tauri WebView 打开搜索页并解析已渲染 DOM。用户提供的 `Ctrl+U` 样本说明，只要拿到页面源码，就不需要复杂的视频接口或播放器接口，普通 HTML 解析已经够用。

建议新增一个“候选采集面板”：

- 左侧仍是建档表单。
- 右侧临时显示 hanime1 搜索/详情页面或解析结果。
- 解析脚本只读取 DOM 文本和图片 URL，不直接写库。
- 采集结果先进入前端草稿对象。
- 保存时仍走现有 `save_archive_draft` / `save_archive_episode_covers`。

这样可以绕开普通后台请求被 403 的问题，也符合你的实际流程：你本来就会自己打开网页核对。

如果第一阶段想更快落地，也可以先支持“粘贴页面源码 txt”：

1. 建档助手增加“导入 hanime1 源码”区域。
2. 用户把搜索页或详情页 `Ctrl+U` 全选复制进去。
3. 软件离线解析候选，不访问网络。
4. 解析成功后填入草稿。

这个方案不够优雅，但稳定、轻量、工程量小，很适合作为解析器验证阶段。

### 后端需要补的闭环

当前代码里 `ArchiveDraft` 有 `getchu_url` 和 `hanime_url` 字段，但 `save_archive_draft` 写出的 `meta.json` 没有 `source` 字段。

这会导致“界面里以后就算填了链接，保存也丢掉”。所以实现自动化前，应先补：

- `ArchiveSaveInput` 增加 `source`
- `ArchiveMetaOutput` 增加 `source`
- 建档表单增加 getchu/hanime1 链接输入或候选写入位置
- JSON 粘贴校验保留兼容

## tag 清洗规则

hanime1 tag 不能原样入库，建议先建立一个可维护的映射表。

### 需要丢弃的 tag

这类 tag 对本地管理没有价值：

- 清晰度：1080p、720p、HD 等
- 字幕/语言：中文字幕、繁體中文、英文字幕等
- 编码/格式：HEVC、MP4 等
- 站点运营标签：热门、推荐、新番等

### 需要人工确认或默认过滤的 tag

用户已明确不想要一部分男性相关 tag。建议做成默认过滤，但保留设置文件可改：

- 男性身体特征类
- 痴汉等用户明确不需要的类别
- 过细、低复用、容易污染筛选器的 tag

### 分类映射

建议继续使用三类：

- `theme`：题材/关系/叙事类型
- `attribute`：角色身份、服装、身体属性
- `scene`：地点、行为场景、镜头/情境

导入时必须以映射表为准。未知 tag 不应直接进数据库，应进入“未分类 tag 待确认”。

## 验收标准

以 `姉SUMMER！` 为第一条验收样本：

1. 搜索候选能找到同名或高度相似条目。
2. 能从搜索页源码识别 2 个候选详情页，并由用户映射到本地第 1/2 集。
3. 第 1 集草稿可填出：
   - 副标题：バ、バカァァッン
   - 发布年月：2011-12
   - 制作商：メリー・ジェーン
   - 本集封面候选
4. 第 2 集草稿可填出：
   - 副标题：す、好きぃぃいっ
   - 发布年月：2012-04
   - 制作商：メリー・ジェーン
   - 本集封面候选
5. tag 先进入待确认区，不直接污染数据库。
6. 保存后不需要重启软件，主库能立即刷新显示。
7. `meta.json` 必须继续保持当前规范，不能把副标题写成“作品名 #1”。

## 风险

1. Cloudflare 拦截会让后台抓取长期不稳定。
2. hanime1 页面结构可能变，解析器要写成“字段缺失可降级”，不能卡死建档流程。
3. 同一作品可能多个版本、合集、补档，必须让用户确认第几集对应关系。
4. tag 分类如果没有白名单/映射表，会继续出现错位和空 tag。
5. 远程封面下载可能失败，必须允许用户拖图或播放取帧兜底。

## 推荐下一步

先不要做大而全的爬虫。第一阶段只做：

1. 建档助手新增 source 字段保存闭环。
2. 新增 hanime1 候选导入面板。
3. 支持用户手动粘贴 hanime1 详情页链接，然后解析单集详情。
4. 做 `姉SUMMER！` 专项验收。
5. 成功后再做站内搜索候选列表。

这样风险最低，也最贴近你的实际流程：信息由软件预填，最后由你确认。
